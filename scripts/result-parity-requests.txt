# One request per line: a name, the file that asks it, the record it is held to, and the
# surfaces it is asked of.
#
# One request leaves three of the compared fields empty: four surfaces agree about the shape
# of `refusals`, `signals` and `warnings` and about no value in any of them. A population is
# what puts a value in each, so the agreement is about something.
#
# The third column is either a baseline file, or `=name` naming another row this one must
# answer identically. A row with neither is a refusal rather than a skip, and so is a request
# file in tests/golden that no row names: two such files sat in this repository wired to
# nothing, which is why this manifest exists.
#
# The fourth column names the surfaces asked, and every row states it rather than leaving it
# to be assumed. A request answered by fewer than two surfaces is a refusal: one surface
# agrees with itself. A surface named in `result-parity-surfaces.txt` that no row asks is a
# refusal too, so a row cannot narrow the population by dropping a surface quietly. Where a
# surface is left off a row, `SURFACES_NOT_ASKED` in `scripts/result_parity.py` states why
# and names the work that would put it on, and a surface that answers anyway reddens the gate
# exactly as loudly as one that stops answering.
#
# A request is added in the same commit as the baseline that holds it, or as the row it is
# declared equal to.
#
# The `plate` row asks the four rules the `quiet` row asks, of the trial it asks them of, and
# states a saved plate as well: the plate's members, one member written over the top, and no
# path or name this machine happens to hold. So the only thing between the two records is what
# each says about the capture, and the numbers hold across the pair. It is the request that
# puts `plate_profile` on a wire and the only one that reports a complete acquisition block.
#
# The `sweep` row asks a different kind of question from the four above it: not what one
# analysis reports, but how far the number moves across a slot's defensible alternatives. Its
# request file names the slots, which is how Python and the browser are asked; the terminal is
# passed none and reads them off the rules the request bound, so the answer's `axes_varied` is
# what holds the two accounts together.
